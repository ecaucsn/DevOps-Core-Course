## Задача 1 — Напишите production Dockerfile (3 балла)

### 1.1 — Одноэтапный Dockerfile

`ВАША ЗАДАЧА`: напишите `app_python/Dockerfile` по скелету ниже. Каждый `___` — ваш. В этой лабораторной **нет полностью готового примера** — к тому моменту, когда Dockerfile даётся целиком, это уже не обучение, а упражнение в наборе текста. Лекция (слайды 11, 13, 14, 15) объясняет *почему* для каждой строки; принесите её с собой.

```dockerfile
# syntax=docker/dockerfile:1
FROM ___                  # ВАША ЗАДАЧА: закрепите slim-базу Python. Почему slim? Почему закреплённую? (слайд 15)
WORKDIR ___               # ВАША ЗАДАЧА: абсолютный путь. Не / и не ~
RUN ___                   # ВАША ЗАДАЧА: создайте ЧИСЛОВОГО непривилегированного пользователя (uid >= 10000)
COPY ___ ___              # ВАША ЗАДАЧА: сначала ОДИН файл — тот, что меняется редко
RUN pip install --___ -r ___  # ВАША ЗАДАЧА: какой флаг не даёт pip запечь свой кеш в слой?
COPY ___ ___              # ВАША ЗАДАЧА: исходники приложения В КОНЦЕ. Объясните логику кеша слоёв в docs
USER ___                  # ВАША ЗАДАЧА: переключитесь на числовой UID из шага выше
EXPOSE ___                # ВАША ЗАДАЧА: на каком порту слушает ваше приложение из лабораторной 1?
# ВАША ЗАДАЧА (рекомендуется): HEALTHCHECK, пингующий GET /health. В slim НЕТ curl и НЕТ wget — выбирайте осознанно
CMD [___]                 # ВАША ЗАДАЧА: exec-форма, не shell-форма (ловушка PID 1 → SIGTERM теряется)
```

**Каждый пропуск — это строка рубрики.** «Хороший» ответ совпадает с рассуждением лекции; «удачный» ответ, который компилируется, но не может быть защищён в `docs/LAB02.md`, потеряет баллы.

### 1.2 — `.dockerignore`

`ВАША ЗАДАЧА`: напишите `app_python/.dockerignore`, чтобы `COPY . .` не отправлял в образ `.git/`, виртуальные окружения, конфиги IDE, `__pycache__/` или `.env`.

```gitignore
# ВАША ЗАДАЧА: укажите как минимум
# - метаданные VCS (утечка .git в Toyota 2022 — слайд 16)
# - кеши Python (__pycache__, *.pyc)
# - виртуальные окружения (.venv, venv/)
# - локальные env-файлы (.env)
# - каталоги редакторов (.idea/, .vscode/)

```

Подсказка: тот же синтаксис, что у `.gitignore`, но оценивается контекстом сборки Docker — *не* git. `.dockerignore` обязателен для этой задачи; его отсутствие стоит всей строки рубрики `.dockerignore`.

### 1.3 — Доказательство выполнения

**Вставьте в `docs/LAB02.md`:**

- Содержимое вашего `Dockerfile` (да, весь файл — он короткий и является оцениваемым артефактом)
- Содержимое вашего `.dockerignore`
- Обоснование одним предложением на каждую строку `# ВАША ЗАДАЧА` — *почему это значение*, а не *что это*
- Вывод `docker build -t devops-info-service:lab02 ./app_python`, показывающий хеш финального образа (иллюстративно — ваши числа будут отличаться)

<details>
<summary>💡 Почему важно каждое правило (прочитайте перед написанием)</summary>

- **Закреплённая slim-база** — `python:3.13` ≈ 1.2 ГБ, `python:3.13-slim` ≈ 150 МБ. Меньше образ = быстрее загрузки (автомасштабирование K8s в лабораторной 9), меньше пакетов = меньше CVE (Задача 4). `:latest` изменяем, поэтому две сборки из «одного и того же Dockerfile» могут дать разные образы.
- **Числовой непривилегированный UID** — CVE побега из контейнера на уровне ядра (например, CVE-2022-0185) даёт root на хосте **если ваш процесс работает от root**. `USER 10001` нейтрализует это. Числовой (в отличие от `USER appuser`) продолжает работать при политиках допуска `runAsNonRoot: true`, которые вы встретите в лабораторной 9+.
- **Порядок слоёв (зависимости до кода)** — каждая инструкция — это кешируемый слой. `COPY . . && pip install` переустанавливает каждую зависимость при каждом изменении кода на 1 символ. `COPY requirements.txt . && pip install && COPY . .` переиспользует слой зависимостей, пока `requirements.txt` действительно не изменится.
- **`--no-cache-dir`** — `~/.cache/pip` у pip — это десятки МБ wheel-файлов, которые вам никогда не нужны в среде выполнения. Слои аддитивны — удаление кеша в более позднем `RUN` НЕ убирает его из образа; оно лишь прячет его за другим слоем.
- **Exec-форма `CMD`** — Shell-форма: `/bin/sh -c "python app.py"` → sh является PID 1, ваше приложение — PID 2, сигналы до вас не доходят. Exec-форма `["python","app.py"]` → ваше приложение *является* PID 1.
- **`.dockerignore`** — Toyota 2022: данные клиентов утекли из-за того, что `.git/` был упакован в развёрнутый образ. Стандартное средство защиты.

Ссылки: [Dockerfile best practices](https://docs.docker.com/build/building/best-practices/) · [Dockerfile reference](https://docs.docker.com/reference/dockerfile/)

</details>

## Задача 3 — Многоэтапная сборка (2 балла)

### 3.1 — Переработайте в две стадии

`ВАША ЗАДАЧА`: перепишите `app_python/Dockerfile` (или создайте `Dockerfile.multi`) как многоэтапную сборку. Стадия **builder** устанавливает зависимости в изолированное место; стадия **runtime** копирует только нужное и не содержит ни `pip`, ни сборочного тулчейна, ни кешей apt.

```dockerfile
# syntax=docker/dockerfile:1
# ---------- Стадия 1: builder ----------
FROM ___ AS builder           # ВАША ЗАДАЧА: та же slim-база (или пожирнее, если нужен gcc для wheel)
WORKDIR ___                   # ВАША ЗАДАЧА: выберите место сборки
COPY requirements.txt .
RUN ___                       # ВАША ЗАДАЧА: установите зависимости в ИЗОЛИРОВАННЫЙ каталог — venv в /opt/venv ИЛИ pip --prefix=/install

# ---------- Стадия 2: runtime ----------
FROM ___ AS runtime           # ВАША ЗАДАЧА: та же slim-база — минимальная финальная поверхность
RUN ___                       # ВАША ЗАДАЧА: снова числовой непривилегированный пользователь (стадии не делят USER)
WORKDIR ___                   # ВАША ЗАДАЧА: абсолютный путь
COPY --from=builder ___ ___   # ВАША ЗАДАЧА: скопируйте ТОЛЬКО каталог зависимостей из builder
ENV PATH="___:$PATH"          # ВАША ЗАДАЧА: добавьте в начало каталог bin вашего venv/prefix
COPY ___ ___                  # ВАША ЗАДАЧА: исходники приложения В КОНЦЕ
USER ___                      # ВАША ЗАДАЧА: числовой UID
EXPOSE ___                    # ВАША ЗАДАЧА: тот же порт, что в Задаче 1
CMD [___]                     # ВАША ЗАДАЧА: exec-форма
```

`ВАША ЗАДАЧА`: зафиксируйте обе строки (`lab02` против `lab02-multi`) и напишите **один абзац** с выводом в `docs/LAB02.md`.

> ⚠️ **Честный вывод, на который вы можете наткнуться:** для **чисто Python**-приложения на Flask многоэтапный образ может быть *немного больше* (например, 133 против 130 МБ), чем одноэтапный — у Flask нет скомпилированных wheel, поэтому нечего выбрасывать из тулчейна, а копия venv добавляет несколько МБ метаданных. **Это ожидаемо.** Задокументируйте это; не выдумывайте уменьшение размера, которое вы не измерили. <details>
<summary>💡 Понятия многоэтапной сборки</summary>

- **Зачем две стадии?** Builder может нуждаться в компиляторе C, чтобы собрать wheel (например, `cryptography`, `psycopg2`). Runtime — никогда. `COPY --from=builder` — это способ выбросить всё, что не нужно среде выполнения.
- **Именование стадий.** `FROM image AS builder`, затем `COPY --from=builder /src /dst`. Имя `AS` — это дескриптор.
- **Где это блестит.** Компилируемые языки. `golang:1.25` ≈ 900 МБ; многоэтапная сборка до `distroless/static` ≈ 15 МБ. Тот же бинарник, в 60 раз меньше, ноль shell, ноль менеджера пакетов. Это и есть Бонус.

Ссылка: [Multi-stage builds](https://docs.docker.com/build/building/multi-stage/)

</details>

<summary>💡 Зачем сканировать, зачем гейтировать по коду выхода</summary>

- `trivy image <ref>` сообщает о CVE в пакетах ОС **и** в зависимостях языка (например, `requirements.txt`).

<details>
<summary>💡 Distroless против scratch — когда что подходит</summary>

- **`gcr.io/distroless/static-debian12`** — пустое пользовательское пространство, кроме CA-сертификатов + `/etc/passwd` (пользователь `nonroot`) + `tzdata`. Рекомендуемое значение по умолчанию для Go.
- **`scratch`** — пусто. ~0 CVE, потому что в образе ничего нет. Работает только для полностью статических бинарников. Вам пришлось бы добавить CA-сертификаты вручную, если ваш бинарник обращается по HTTPS.
- **Компромисс** — отсутствие shell означает отсутствие `docker exec ... sh` для отладки в продакшене. Это *преимущество* под атакой и *помеха* во время разработки. Держите под рукой вариант `*-debug` distroless, если он нужен вам локально.

<details>
<summary>⚠️ Частые ошибки (из реальных прогонов)</summary>

- **`COPY . .` перед `pip install`** — убивает кеш слоёв. Изменение кода на один символ переустанавливает каждую зависимость. Самая частая ошибка в этой лабораторной — исправьте её, скопировав сначала `requirements.txt` и выполнив `pip install` до остальных исходников. (Слайд 14 лекции.)
- **`USER appuser` (не числовой) при `runAsNonRoot: true`** — работает в Docker, но не проходит политику допуска K8s в лабораторной 9, потому что не может проверить UID без разбора `/etc/passwd`. Всегда используйте **числовой** `USER 10001`.
- **Trivy DB `ghcr.io ... DENIED`** — кампусные / ограниченные сети ограничивают анонимный токен ghcr.io по скорости. Используйте `--db-repository public.ecr.aws/aquasecurity/trivy-db:2` — Aqua публикует там явно для этого случая.
- **В `python:3.13-slim` нет `curl` и нет `wget`** — ваш HEALTHCHECK молча ломается. Либо используйте `python -c 'import urllib.request; urllib.request.urlopen("http://127.0.0.1:8080/health")'`, либо `apt-get install curl` (и примите дополнительные CVE). Не добавляйте строку и не предполагайте, что она работает.
- **Trivy `v0.69.4` вредоносен** — компрометация цепочки поставок CVE-2026-33634 (март 2026). Закрепляйте `v0.69.3` или более поздний чистый патч. В CI: `trivy-action@v0.35.0+`.
- **BuildKit не включён** — старые Docker Engine (<23) игнорируют `# syntax=docker/dockerfile:1` и пропускают возможности `COPY --from=builder`. В Docker 29 BuildKit включён по умолчанию; если ваша сборка падает на синтаксисе `RUN --mount=type=cache`, вы на древнем Docker.
- **`.dockerignore` отсутствует** — ваш `COPY . .` отправляет `.git/`, `.venv/`, конфиги IDE и **`.env` с секретами** в образ. Слои вечны — как только секрет в образе, даже удаление его в более позднем слое не убирает его.
- **`COPY secrets.env / && rm secrets.env`** — НЕ удаляет секрет. Он всё ещё в более раннем слое, виден через `docker history` и `docker save | tar -xvf`. Рассматривайте каждый слой как неизменяемый.
- **Многоэтапная сборка немного БОЛЬШЕ для чистого Python** — у Flask нет скомпилированных wheel, поэтому стадии builder нечего выбрасывать, а копия venv добавляет ~3 МБ. Это **ожидаемо и правильно** — задокументируйте это, не скрывайте. Большой выигрыш многоэтапной сборки — компилируемые языки (бонусная задача).
- **Кеш образа устаревает после `apt-get update`** — если вы выполняете `RUN apt-get update && apt-get install foo` в двух отдельных слоях, `update` кешируется навсегда, а `install` перезапускается против устаревшего списка пакетов. Всегда объединяйте их в одном `RUN`. Тот же урок, другой менеджер пакетов: не разделяйте связанную работу по слоям.
- **Имя хоста контейнера — это ID контейнера, а не ваш ноутбук** — `socket.gethostname()` внутри контейнера возвращает что-то вроде `a3f29c8b1d04`. Это правильное поведение (сноска лабораторной 1), а не баг. Вы видите в действии пространство имён PID/UTS.
- **`docker run` по умолчанию от root** — даже если в вашем Dockerfile `USER 10001`, `docker run --user root` переопределяет его. Dockerfile задаёт *значение по умолчанию*; среда выполнения может переопределить. В лабораторной 9 Kubernetes PSA / политики безопасности Pod обеспечивают это со стороны оркестратора.

</details>
